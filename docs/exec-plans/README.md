# docs/exec-plans/README.md

> 실행 계획 디렉터리의 운영 규칙입니다.

## 역할 분리

- `docs/PLANS.md`는 마일스톤, 우선순위, 큰 목표를 관리한다
- `docs/exec-plans/active/`는 지금 실제로 수행 중인 작은 단위 실행 계획만 관리한다
- `docs/exec-plans/completed/`는 완료, 취소, 대체됨 상태의 실행 계획을 보관한다

## 시작 규칙

1. 사용자 명령을 받으면 먼저 작업을 검증 가능한 최소 단위까지 쪼갠다.
2. 목표, 범위, 변경 대상, 검증, 종료 조건이 있는 실행 계획 문서를 작성한다.
3. 작성한 문서를 `docs/exec-plans/active/`에 기록한 뒤 `worktree`를 준비하고 작업을 시작한다.

## 크기 규칙

- 실행 계획 하나는 하나의 명확한 목적만 다룬다
- 한 번의 검증 사이클로 닫을 수 없는 큰 범위라면 더 쪼갠다
- 마일스톤 전체 태스크 표를 `active/`에 장기 보관하지 않는다
- stale 상태가 된 실행 계획은 같은 턴에 갱신하거나 종료 처리한다

## 권장 구성

- 상태
- 마일스톤
- 목표
- 범위
- 제외 범위
- 변경 대상
- 검증
- 종료 조건
- 작업 목록
- 완료 결과

## 종료 규칙

1. 작업이 끝나면 결과와 검증 내역을 문서에 남긴다.
2. 상태를 `완료`, `취소`, `대체됨` 중 하나로 갱신한다.
3. 문서를 `docs/exec-plans/completed/`로 이동한다.
4. 종료 기본 명령은 `./harness.sh ship <task-id> <commit-message> develop`이며, 이 단계에서 completed 이동, 커밋, `develop` 머지, 완료 보고까지 끝낸다.
5. `docs/PLANS.md`, `active/README.md`, 관련 문서와 상태를 맞춘다.
6. 머지 권한이나 환경 제약으로 `develop` 반영이 끝나지 않았다면 완료로 간주하지 말고 그 상태를 명시한다.
