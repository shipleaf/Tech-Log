# docs/design-docs/core-beliefs.md

> 이 문서는 Codex가 모든 결정을 내릴 때 기준으로 삼아야 하는 핵심 신념입니다.
> 코드 생성, 설계 결정, 트레이드오프 선택 시 이 원칙을 최우선으로 적용합니다.

---

## 1. 단순함이 기능보다 먼저다

좋은 블로그는 빠르고, 읽기 좋고, 유지보수가 쉽다. 기능을 추가하기 전에 "이게 없으면 블로그가 안 되는가?"를 묻는다.

## 2. 콘텐츠가 왕이다

모든 UI, 성능 최적화, 기술 선택은 글을 잘 보여주기 위한 것이다. 기술이 콘텐츠를 압도해서는 안 된다.

## 3. 에이전트가 이해할 수 있는 코드를 쓴다

인간이 아니라 다음 Codex 세션이 읽을 코드를 쓴다. 명확한 이름, 명시적 타입, 짧은 함수가 "영리한" 코드보다 낫다.

## 4. 실패는 하네스의 문제다

에이전트가 같은 실수를 반복하면, 에이전트를 탓하지 않는다. 그 실수를 불가능하게 만드는 린터, 테스트, 또는 문서를 추가한다.

## 5. 문서는 코드다

문서가 오래되면 코드도 오래된 것과 같다. 기능 변경 시 문서 업데이트는 선택이 아니라 완료 조건(Definition of Done)이다.

## 6. 점진적으로 배포한다

큰 PR은 리뷰하기 어렵고, 롤백하기도 어렵다. 작고 검증 가능한 단계로 나눈다.
