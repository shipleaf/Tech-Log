# 파일 기반으로도 충분한 이유

초기 기술 블로그에서는 데이터베이스보다 **글을 빨리 남길 수 있는가**가 더 중요합니다.

MDX 파일 기반 접근은 다음 장점이 있습니다.

- Git 이력으로 수정 내역을 바로 추적할 수 있습니다.
- 코드 예제와 설명을 한 파일에서 함께 관리할 수 있습니다.
- 배포 전에 `build`, `lint`, `test`로 검증하기 쉽습니다.

## frontmatter에서 관리하는 것

현재 포스트 메타데이터는 아래 항목만 사용합니다.

- `title`
- `description`
- `date`
- `tags`
- `published`

```mdx
---
title: "새 포스트 제목"
description: "목록과 메타 설명에 쓰일 한 줄 요약"
date: "2026-04-15"
tags: ["nextjs", "mdx"]
published: true
---
```

```json
{
  "title": "새 포스트 제목",
  "description": "목록과 메타 설명에 쓰일 한 줄 요약",
  "date": "2026-04-15",
  "tags": ["nextjs", "mdx"],
  "published": true
}
```

이 정도만 있어도 목록 정렬, 상세 페이지 메타데이터, 읽기 시간 계산까지 무리 없이 연결됩니다.
